# CG5 評価課題1 提出資料

## 1. 必須内容について
**「Grayscaleを利用したシーンの描画」**
本プロジェクトでは、ポストエフェクトの一つとして Grayscale を実装し、要件を満たしています。プログラム内では PostProcessMode::Grayscale や、後述の「個別オブジェクトへのマスク適用」等で呼び出し可能な状態です。

## 2. 実装した加点要素（指定項目）
スライドに記載された加点要素のうち、以下の項目を実装しています。
これらは実際のゲームのグラフィック表現として組み込んでいます。

* **Vignetting (3点)**
  * GameScene において画面全体に適用し、画面の四隅を暗く落とすことでゲーム画面の雰囲気作りに利用しています。
* **LuminanceBasedOutLine (5点) / DepthBasedOutLine (8点)**
  * これらはゲームシーン（InGame）内に配置されている「建物」などの特定オブジェクトに対して適用し、トゥーン調や強調表現として利用しています。
* **Radial Blur (5点)**
  * ゲーム内の特定オブジェクト等のマスク処理に組み込んでいます。
* **Random [Noise] (4点)**
  * ランダム要素としてノイズフィルタを実装し、一部オブジェクトの表現として活用しています。
* **BoxFilter (3点)**
  * Smoothing フィルタとして実装しています。
* **GaussianFilter (5点)**
  * 画面全体にぼかしを入れる用途等で実装しています。
* **Dissolve (4点)**
  * ノイズテクスチャの閾値を利用した消失表現（ディゾルブ）を実装しています。

## 3. 「その他」枠としての独自実装 (20点)
加点要素の「その他」枠として、課題で指定されたもの以外にも独自のポストエフェクトを実装し、ゲームシステムへ統合しています。また、単なる画面フィルタとしてではなく、特定の表現を行うための独自の仕組みを導入しました。

### ① マスクベースの個別オブジェクトPostEffect適用システム
通常のポストエフェクトは画面全体に一律でかかりますが、本プロジェクトでは **「特定の3Dモデル（オブジェクト）にだけ、個別のポストエフェクトを適用する」システム（EffectMaskComponent）** を構築しました。
* **技術詳細**: 描画パスにおいて、各オブジェクトの Instance ID を独自のマスクバッファ（テクスチャ）に書き込みます。その後の PostProcess シェーダー側でマスクを参照し、ピクセル単位で適用するエフェクトを分岐させています。
* **効果（個別適用）**: これにより、「建物Aだけモザイク」「建物Bだけ色収差とグリッチ」「建物Cだけアウトライン」といった、オブジェクト単位での柔軟なエフェクト表現が可能になっています。
* **効果（グローバルエフェクトからの除外機能）**: マスクが適用されたオブジェクトは、画面全体にかかるエフェクト（ガウスぼかしやビネットなど）の影響から外れるようにシェーダー内で排他処理を行っています。これにより、「背景にはエフェクトがかかっているが、特定のオブジェクトだけは通常通り描画する」といった演出を行っています。

### ② 独自のカスタムエフェクト実装
本プロジェクトでは、課題で指定されたもの以外にも以下のカスタムエフェクトを実装し、実際のゲームシーンに組み込んでいます。
* **ゲームに組み込み済みの独自エフェクト**:
  * **Glitch**: 色収差とノイズを組み合わせた映像の乱れ
  * **Pixelation**: ドット絵化・モザイク
  * **Pointillism**: 点描画風フィルタ
  * **Posterization**: アニメ塗り・階調化
  * **NightVision**: 暗視ゴーグル風
  * **Kaleidoscope**: 万華鏡のような幾何学的反射
  * **ChromaticAberration**: 色収差
  * **DisplacementMap**: テクスチャによる画面の歪み・陽炎表現
  * **Halftone**: 網点・コミック調
* **その他の描画技術（ポストプロセス拡張）**:
  * 高輝度部分を抽出して発光させる **Bloom**
  * ガウスぼかしの代替手法としての **Dual Kawase Blur**
  * 深度バッファを活用した **Depth of Field (被写界深度)**
  * 光の筋を生成する **Light Shafts (ゴッドレイ)**
  * 物理ベースレンダリング向けの **ToneMapping (ACES等)**
  * その他、**HSV色空間補正**, **Sepia**, **Directional Blur (方向ブラー)**, **Fade / Slide** といった多様なエフェクトを実装しています。

* **シェーダーの計算アプローチ（実装の工夫）**:
  * **色空間の高度な変換処理**: `HSV`色調補正などのエフェクトでは、ピクセルシェーダー内でRGB値を一度HSV色空間に変換する数式計算（`RGBToHSV` / `HSVToRGB`）を挟むことで、色相や彩度を直感的かつ正確にコントロールできるように実装しています。
  * **三角グリッドベースの高品位ノイズ (Simplex Noise)**: `DisplacementMap`（陽炎表現）などの計算において、標準的な四角形の乱数ノイズではなく、計算処理に「正三角形のグリッド（Simplex）」を用いる `Simplex Noise (sFBm)` をシェーダー内で実装しています。これにより、縦横の不自然なアーティファクト（格子状の歪み）が出ない高品質な表現を実現しました。
  * **UV座標の数学的操作**: ピクセレーションや万華鏡、方向ブラーなどは、ピクセルシェーダー内でUV座標に対して数式による変換（グリッドへのスナップ、回転行列による演算、ベクトル加算など）を行い、テクスチャのサンプリング位置を意図的にずらすことで実現しています。
  * **色空間の分離と階調制御**: グリッチや色収差では、RGBチャンネルごとのサンプリング座標を個別にずらすことで色の分散を表現しています。またポスタリゼーションでは、色を段階的に丸め込む計算（`floor`関数の活用など）によってトゥーン調の階調化を行っています。
  * **マルチパスレンダリングの活用**: Bloomや被写界深度（DoF）、Dual Kawase Blurといった高度なエフェクトでは、1つのシェーダー内で完結させず、輝度抽出・ダウンサンプリング・ブラー処理といった複数の描画パス（RenderTexture間の受け渡し）を経て最終結果を加算合成するアプローチを採用しています。

### ③ ゲーム基盤としての連携機能（CG4までの成果の統合）
ポストエフェクトの適用にあたり、前課題（CG4）までに構築した以下のエンジン機能と組み合わせてゲームシーンを構築しています。
* **GPU Compute Shaderによる並列スキニング & GPU Particle**
  * 頂点計算やパーティクル制御（VortexなどのField制御含む）をGPU側で行い、CPU負荷を軽減しています。
* **MultiMesh & MultiMaterial / Bone Attachment**
  * キャラクターの部位ごとの質感変更や、アニメーションするボーンへのアイテム（武器やエミッター）の追従装着を実現しています。
* これらの描画結果に対して今回のPostEffectとマスクシステムを適用することで、柔軟な表現を実現しています。

これらはエディタ（JSONデータ）上からオブジェクトごとに割り当てることが可能です。

### ④ レイヤー別エフェクト管理とRenderGraph統合 (モダンなレンダリングパイプラインの構築)
本エンジンでは、描画パイプラインを `RenderGraph` アーキテクチャを用いて構築しており、ポストプロセスの適用タイミングをUI描画の「前」と「後」で厳密にレイヤー分離して管理する仕組みを実装しました。

* **Pre-UI (UI描画前) エフェクト**:
  Bloom（ブルーム）や被写界深度（DoF）、オブジェクトごとの固有エフェクトなど、3Dのゲーム世界（背景やキャラクター）にのみ適用します。これにより、体力ゲージやImGuiなどのUIがぼやけたり発光したりするのを防ぎ、UIの視認性を保ちます。
* **Post-UI (UI描画後) エフェクト**:
  画面遷移時の Fade（暗転）や Dissolve、画面全体にかかるビネットやノイズなど、UIを含めた「最終的な出力画面全体」に対して適用します。

このレイヤー分離により、単一のポストプロセス処理では実現不可能な「奥の背景はピンボケしているが、手前のUIはくっきり見え、最後に画面全体が暗転する」といった、破綻のない描画フローを実現しています。
