# CG4 評価課題 提出資料

## 操作方法

Editorの上中央にある再生ボタンのようなマークをクリックするとUnityのようにSceneの更新が始まります。
ヒエラルキーでそれぞれの情報を見たりすることができます。


## 実装した加点要素について

本プロジェクトでは、スライドで提示された加点要素のうち、以下の項目を実装しております。

### 1. Skinningモデルの表示 (20点)
- `SkinnedMeshRendererComponent` を実装し、`.gltf` や `.glb` フォーマットのアニメーション付きモデルを正しく描画できるように対応しています。
- シーン上には、プレイヤーカーソルの入力で動かせる歩行モデルや、`BrainStem.glb` など複数のスキニングモデルが配置されています。
- 操作に関してはキーボードWASDまたはコントローラー左スティックに対応しています。

### 2. コンピュートシェーダーによるスキニング (10点)
- `Skinning.CS.hlsl` を用い、CPU ではなく GPU (Compute Shader) 上で並列にスキニング（ボーンによる頂点変形）を行っています。
- これにより、CPU の演算負荷を解放し、計算後の頂点バッファを直接描画パイプラインへ効率的に送るアーキテクチャを採用しています。

### 3. MultiMesh & MultiMaterial対応 (5点)
- **MultiMesh**: SkinCluster を拡張し、複数メッシュを持つGLTFモデルがそれぞれ正しいボーンウェイトと頂点オフセットを参照できるように対応しました（頂点爆発バグを解決）。
- **MultiMaterial**: 各部位（マテリアルスロット）ごとに色や質感（Metallic/Roughness）を独立して上書き（Override）できる機能を追加しました。エディタの Inspector から動的に編集でき、シーンへのシリアライズにも対応しています。

### 4. Animation補間 (5点)
- `AnimatorComponent` と `AnimationManager` において、フレーム間の姿勢補間ロジックを実装しています。
- また、アニメーションの切り替え時（待機 ↔ 歩行 ↔ しゃがみ等）に、`fadeDuration`（フェード秒数）を用いたアニメーションブレンド（クロスフェード）が行われ、モーションが滑らかに遷移します。
- 歩き、しゃがみの切り替えはCtrlキーもしくは左スティック押し込みで切り替わります。

### 5. 骨のデバッグ表示 (10点)
- `SkeletonDebugRendererComponent` を実装し、ボーン階層を X-Ray（最前面）表示する機能を備えています。
- 関節部分はスカイブルーの球 (Sphere) で、骨の部分はピンクの八面体 (Octahedron) でそれぞれ描画され、アニメーションの動きをエディタ上で視覚的にデバッグ可能です。

### 6. GPU Particle (最大30点相当の内容)
スライド内で提示されたGPU Particleの拡張要件について、以下の機能を実装しました。
- **Emitterの拡張**: 
  - **複数のEmitterを作れる**: `ParticleEmitterComponent` を通じて、シーン内に任意に複数のエミッターを配置・管理できるようにしました。
  - **タイプの追加**: 基本の形状である球 (Sphere) や箱 (Box) に加え、円柱 (Cylinder)・リング (Ring)・ビーム (Beam)・半球 (Hemisphere) といった多彩なエミッター形状タイプを実装しました。
- **Particleの拡張**:
  - **制御パラメータを増やす**: 寿命、初速、重力、減衰（Damping）、バウンス、時間経過による色やスケールの変化など、詳細な制御パラメータを持たせました。
  - **Particleタイプの追加**: 飛翔中に軌跡を描く **「Trail (軌跡)」** や、寿命が尽きた際に破裂する **「Death Emit」** パーティクル機能をコンピュートシェーダ上で追加しました。
- **Fieldの拡張**:
  - **CG3で学んだFieldをGPU Particleで実現**: GPU側のパーティクル座標に対して直接影響を与えるベクトル場（Field）を実装しました。
  - **様々なタイプの作成**: 「Directional（風・重力）」「Point Attractor（引力・斥力）」に加え、**「Vortex（渦）」** を実装し、CG4シーンで実際に渦を巻くフィールドを配置しています。
- **使いやすいEditor機能**:
  - パーティクルの形状やFieldの強さ、色などの膨大なパラメータを、エディタ（ImGui）のプロパティウィンドウからリアルタイムに調整・保存できるUIを完備しています。

### 7. 指定した骨へのアイテムの装着機能 (10点)
- アニメーションして動いているキャラクターの任意のボーン（関節）に他のオブジェクトを追従させる `BoneAttachmentComponent` を実装しました。
- このコンポーネントはボーンのワールド行列から**位置だけでなく回転（Euler角）も抽出して同期**するため、キャラクターのモーションに合わせて装着アイテムも正しく回転します。
- 今回のプロジェクト（CG4シーン）では、以下の2つの実装例を用意しています。
  - **パーティクルの追従**: プレイヤー（`sample/walk.gltf`）の右手ボーン（`"mixamorig:RightHand"`）にエミッターを追従させ、「動く手から魔法のパーティクルが放出され続ける」処理を実現。
  - **武器の追従**: 左手ボーン（`"mixamorig:LeftHand"`）に円柱プリミティブ（木の棒）を追従させ、走るモーションに合わせて武器を振る様子を実現。
- このように汎用コンポーネントをアタッチするだけで、任意のキャラクターモデルに対して武器やアイテムの持たせ替えが即座に可能となっています。

### 8. その他 (30点)
※SkinningやSkeleton、Animationに関連する独自の拡張・高品質化対応（技術的詳細）

- **GPU Compute Shaderによる並列スキニングアーキテクチャ (`Skinning.CS.hlsl`)**: 
  - 従来CPUで行われがちな頂点ウェイトの乗算処理をすべてGPU側にオフロードしました。毎フレームの `SkinCluster` データ（各ボーンの `Matrix4x4`）を定数バッファ(CBV)としてGPUへ転送し、コンピュートシェーダー内で頂点の位置・法線・接線を並列計算しています。
  - 計算結果は UAV (Unordered Access View) を通じて `StructuredBuffer` に直接書き込まれ、そのバッファをそのまま描画パイプラインの頂点シェーダー (`SkinningObject3D.VS.hlsl`) へ渡す設計にすることで、CPU-GPU間の不要なデータ転送ボトルネックを排除。大量のボーンと頂点を持つモデルでも極めて高いパフォーマンスを誇ります。

- **高度なアニメーションブレンドと姿勢補間アルゴリズム (`AnimatorComponent`)**: 
  - フレーム間のカクつきを無くすため、キーフレーム間の補間処理として、移動量 (`Vector3`) には **Lerp (線形補間)**、回転量 (`Quaternion`) には **Slerp (球面線形補間)** を適用し、数学的に正しい姿勢ブレンドを行っています。
  - さらに、モーション切り替え時（待機から歩きなど）には `fadeDuration` の設定値に基づき、現在のアニメーションツリーと次のアニメーションツリー間で重み付け(Weight)ブレンドを行う「クロスフェード処理」を実装。不自然な姿勢の飛び(ポッピング)を防いでいます。

- **Deferred Rendering (遅延レンダリング) および Post-Process との完全な統合**: 
  - Compute Shaderで計算されたスキニングメッシュは、静的モデルと同様にG-Buffer (Albedo, Normal, Material[Metallic/Roughness]) へ正しく出力されるよう設計されており、エンジンの物理ベースレンダリング(PBR)の恩恵を完全に受けることができます。
  - 同様に、追加実装したGPUパーティクルも深度バッファ(Depth Buffer)との完全な連携が取れており、ブルーム(Bloom)や被写界深度(Depth of Field)などのポストエフェクトと破綻なく調和します。

- **エディタ主導のリアルタイムデバッグ環境 (`SkeletonDebugRendererComponent` / `ImGui`)**: 
  - アニメーションの構造解析を容易にするため、最前面(Z-Test無視)でボーン構造を描画するデバッグレンダラーを実装。関節位置(Sphere)と骨格(Octahedron)を可視化しました。
  - さらにエンジンの `ComponentEditorRegistry` を介して ImGui に統合されており、アニメーションの再生速度、ブレンド時間、パーティクルの全パラメータ（放射タイプ、初速、拡散率など）をプログラムの再ビルドなしにリアルタイムで調整可能な環境を構築しています。

- **非同期読み込み時の排他制御と数学的バグ(NaN)の完全改修**: 
  - アニメーション付きGLTFモデルをマルチスレッドで非同期ロードする際、リソース解放順序の不整合による Use-After-Free バグを修正し、安全なスレッドセーフ設計としました。また、ごく一部の特殊なアニメーションデータで発生する「時間が NaN（ゼロ除算）になる不具合」に対する堅牢な例外処理(サニタイズ)を追加実装しています。
